# 第一阶段基础 RAG 方案

> 文档状态：讨论稿
>
> 当前仅记录已确认背景和待确认事项，不作为最终编码方案。最终实施方案和验收标准将在后续讨论确认后更新。

## 1. 阶段目标

第一阶段实现可以完整运行的基础 RAG 后端流程，包括同步文档入库和在线检索问答。实现以验证端到端流程为目标，不在本阶段提前引入检索优化、异步任务或额外业务管理能力。

## 2. 已确认范围

### 2.1 离线文档入库

- 接收 PDF、DOC/DOCX、TXT 和 Markdown 文档。
- 为上传文档生成 UUID v4 唯一标识。
- 将原始文档保存到 MinIO。
- 使用 Apache Tika 提取文档文本内容。
- 使用基础分块方式将文本切分为多个片段。
- 使用 `qwen3.7-text-embedding-flash` 将文本片段转换为 1024 维向量。
- 将文本片段、向量及来源信息保存到 Milvus。
- 同步返回文档入库结果。

### 2.2 在线检索问答

- 接收用户问题。
- 使用 `qwen3.7-text-embedding-flash` 将问题转换为向量。
- 从 Milvus 中检索相关文本片段。
- 将用户问题与检索内容组装为上下文。
- 使用 `qwen3.7-flash` 生成回答。
- 向用户返回回答。

## 3. 非本阶段范围

第一阶段不实现以下内容：

- 文档异步入库、任务队列和处理状态查询。
- MySQL 等业务数据库。
- 文档管理、删除和重新入库。
- OCR 和扫描件识别。
- 分块策略优化。
- Query 改写。
- 关键词检索与混合检索。
- 检索结果重排。
- 前端项目。

## 4. 核心流程

### 4.1 离线文档入库流程

```text
用户上传文档
→ 系统生成文档唯一标识
→ 保存原始文档
→ 提取文档文本内容
→ 将文本切分为多个片段
→ 将文本片段转换为向量
→ 保存文本片段、向量和来源信息
→ 返回文档入库结果
```

### 4.2 在线检索问答流程

```text
用户提交问题
→ 将问题转换为向量
→ 检索与问题相关的文本片段
→ 将用户问题和检索内容组装为上下文
→ 调用大模型生成回答
→ 向用户返回回答
```

## 5. 已确认技术决策

- 后端采用单体多模块架构，由 `nexus-rag-bootstrap` 统一启动。
- 离线入库和在线问答分别由 `OfflinePipeline`、`OnlinePipeline` 编排。
- 第一阶段的文档入库采用同步处理。
- 原始文档保存到 MinIO，文档文本使用 Apache Tika 提取。
- 向量和文本片段保存到 Milvus。
- 对话模型使用 `qwen3.7-flash`。
- 向量模型使用 `qwen3.7-text-embedding-flash`，向量维度为 1024。
- 文档唯一标识使用 UUID v4。
- API Key 等敏感配置只通过本机环境变量提供。
